# Gavel Gate MVP Implementation Plan

> **NORMATIVE SPEC WINS:** [`../GAVEL_GATE_TECHNICAL_SPEC.md`](../GAVEL_GATE_TECHNICAL_SPEC.md) is the implementation contract. This checked-in plan is an execution document and MUST be corrected when it drifts; on every conflict, the technical specification wins. The original external attachment remains untouched.
>
> **For Hermes:** Use `subagent-driven-development` to implement each PR with a fresh agent, then run spec-compliance and code-quality review before merging.

**Goal:** Ship an experimental Base-USDC Gavel Gate MVP in one week: opted-in governance participants publish a public Gate, advocates submit one immutable paid pitch, and a confirmed atomic settlement synchronously creates a private inbox item without exposing delivery or voter-private data.

**Architecture:** Gate is a writable feature beside—not inside—the existing reconstructable governance index. The index remains canonical and read-only. `@gavel/gate` owns reusable schemas, policy, adapters, fact provenance, and quote construction; `packages/server` is the intended/canonical reserved server boundary that will become the single Railway/self-hosted HTTP service and own hosted routes, Postgres writes, signer access, settlement watching, and notifications. Its package documentation or `package.json` may currently be empty/reserved; do not infer an existing HTTP implementation. Gate adds routes and workers under `packages/server/src/gate/`; it does not create a parallel backend. A minimal Foundry splitter performs one Base native-USDC EIP-3009 pull and atomically routes the voter’s full attention price plus Gavel’s fixed fee.

**Tech stack:** Existing CommonJS monorepo supporting Node >=20 (CI may test Node 20 and 22), `ethers` v6, `zod`, Postgres 16, Node test runner; new Foundry project for Solidity; new React/Vite TypeScript app for the Gate web UI; Base native USDC EIP-3009; EIP-712; ERC-1271.

**MVP product boundary:** Nouns only; Base USDC only; Gate availability `accepting_now | paused | closed` (these lowercase literals are the only code/DB/API/EIP-712 values); Nouns `VOTING` policy only (normalized `PRE_VOTE` vocabulary is retained but is not exposed without a separately frozen, implemented, and tested native mapping); public directory/profile; wallet enrollment; EOA payers for Base EIP-3009 plus EOA or ERC-1271/Safe enrollment/governance/voter payout identity; immutable single paid pitch; display-only HTTPS evidence URLs; one notification adapter. No contract-wallet/Safe payers, replies/follow-ups, uploads, server-side evidence fetching, Markdown HTML, async paid evaluation, refunds, custody, clawback, percentage fees, persuasive-score model, fact/rhetoric LLM, multi-chain settlement, or arbitrary payout redirection.

## Non-negotiable implementation rules

1. **No production code without a failing test first.** Every code task follows RED → GREEN → REFACTOR; record the command used for RED and GREEN in the PR description.
2. **Do not modify the governance index’s public API into a write API.** Gate calls/reads the index through a narrow client and owns all private/write tables.
3. **Do not touch the untracked `workers/gavel-index-api/` in Gate PRs.** It is an independent, GET/HEAD-only public index proxy and cannot safely own Gate writes or signing.
4. **All money moves only through the splitter.** The canonical Gavel server never receives, stores, refunds, forwards, approves, or sweeps USDC.
5. **Quote issuance happens only after every cheap deterministic check passes.** After confirmed settlement, create the inbox item synchronously; only notifications may be async.
6. **Raw advocate text is never an instruction.** Preserve it as a record, render only the specified CommonMark subset, never feed it to an agent/tool/runtime, and never fetch evidence URLs.
7. **Keep private and public serializers distinct.** Public responses must not be constructed by stripping fields from private persistence objects.
8. **Use explicit, injectable clocks/RPC clients/signers in domain code.** This keeps quote expiry, rolling capacity, confirmation tests, and adversarial tests deterministic.

## Frozen MVP contract

### Economic and settlement contract

- DAO policy attention price is per-DAO, integer USDC atomic units, minimum `1_000_000` (USDC $1).
- Fixed Gavel service fee is `250_000` native-USDC units ($0.25), disclosed separately and paid to the immutable Gavel recipient.
- Enrolled Gate wallet is the payout wallet. There is no payout override.
- One checkout transaction settles exactly `attentionPrice + gavelFee` through a Base splitter.
- The voter receives **100%** of `attentionPrice`; Gavel receives only the fixed $0.25 fee.
- Final settlement is non-refundable. Gavel guarantees correct quote verification, routing, recording, and inbox creation—not voter attention, persuasion, notification receipt, or dispute resolution.
- User disputes are outside Gate; no contract refund, clawback, escrow, rescue, sweep, admin, upgrade, or custody path exists.
- The advocate/payer is EOA-only for the MVP Base native-USDC EIP-3009 `v,r,s` authorization. ERC-1271 applies only to enrollment/governance authority and voter payout identity. Base-sender session/checkout and quote issuance reject contract-wallet payers before quote creation; Safe payer support is post-MVP and does not change the splitter ABI.

### Quote and settlement lifecycle

```text
DRAFT (not persisted)
  └─ pre-payment validation fails → NO SUBMISSION ARTIFACTS PERSISTED
                                      (private aggregate rate-limit events may persist)
  └─ validation + atomic submission/snapshot/quote/reservation → QUOTED / payment_required (10 min)
       ├─ wall-clock expiry → EXPIRED + EXPIRY_PENDING_RECONCILIATION
       │                       (payment-terminal; capacity still reserved until scanner-safe release)
       ├─ browser tx hash optionally supplied → SETTLEMENT_PENDING (latency hint only)
       │    ├─ genuinely pending/unconfirmed → SETTLEMENT_PENDING
       │    ├─ reverted/dropped/mismatched/no expected event → QUOTED / public payment_required while valid
       │    │                                                    └─ quote expiry → EXPIRED
       │    └─ expected QuoteSettled event + Base confirmationDepth=1
       │          └─ atomic idempotent DB commit → SETTLED + RESERVATION CONSUMED/CAPACITY COUNTED
       │                                           + INBOX_CREATED + NOTIFICATION ENQUEUED
       │                                           + SETTLEMENT_REORG_MONITOR UPSERTED
       │                                                 └─ notification job → NOTIFICATION_PENDING → SENT | FAILED
       └─ valid quote remains honorably payable if Gate is paused/closed or policy changes
```

`notification_*` is private operational state. Do not expose `delivered`, `read`, open, click, channel, or retry state to an advocate. `INBOX_CREATED` is the only paid-service completion condition.

Settlement expiry is decided by receipt block timestamp, not watcher wall clock: an event included strictly before quote expiry wins even if confirmed or processed later; equality or later is invalid. Local/public `expired` is payment-terminal for browser checkout and new payment attempts, but wall clock only moves the reservation to `expiry_pending_reconciliation`; it does not free capacity. The one-confirmation-safe scanner releases only when its crash-safe cursor/range transaction proves coverage of every eligible Base block that could contain a valid event with receipt block timestamp `< quote.expiry` and finds no match. A matching event found first consumes atomically. Exceptional later overlap/reorg discovery converts released to consumed and creates the paid inbox. The browser never submits a new authorization after expiry.

Settlement discovery is independent of browser tx hashes. A durable forward cursor per chain/splitter starts at deployment and scans through the one-confirmation-safe head. Every cycle also rescans a configurable trailing overlap, default 64 Base blocks, and compares canonical block hashes/exact log identities with stored accepted evidence. Cursor advancement and range recording are atomic or equivalently crash-safe. A durable bounded-batch monitor queue revalidates every accepted receipt block hash and exact log on every cycle through a one-time final check at 64 canonical confirmations. Restart resumes cursor and queue; downtime never skips the final check.

One confirmation is application finality. A detected post-acceptance reorg records private `settlementReorgedAt`, anomaly, and alert but never changes public acceptance/inbox/capacity or performs financial action. A deeper reorg after the 64-confirmation automatic-monitoring horizon is accepted residual operational risk and may be found only by operator reconciliation; do not claim perpetual automatic detection.

### Quote EIP-712 schema

The EIP-712 domain is bound to the Base splitter deployment:

```ts
const domain = {
  name: 'GavelGateSplitter',
  version: '1',
  chainId: 8453, // configured; Base Sepolia in test deployment
  verifyingContract: splitterAddress,
};

const Quote = [
  { name: 'quoteId', type: 'bytes32' },
  { name: 'payer', type: 'address' },
  { name: 'voter', type: 'address' },
  { name: 'attentionAmount', type: 'uint256' },
  { name: 'gavelFeeAmount', type: 'uint256' },
  { name: 'submissionHash', type: 'bytes32' },
  { name: 'token', type: 'address' },
  { name: 'expiry', type: 'uint256' },
  { name: 'quoteVersion', type: 'uint256' },
];
```

`chainId` and `verifyingContract` belong in the domain, not duplicate unsigned application fields. Domain construction/signing, splitter validation before USDC, and server settlement verification MUST require `quote.quoteVersion == 1`; unsupported versions fail closed. Persist every signed value and the Gavel quote signature. In one issuance transaction before signing/returning the quote, create immutable quote → submission → issuance-snapshot FKs; the snapshot stores canonical content hash. Quote typed data binds `submissionHash`, not `snapshotId` or snapshot content hash directly. Do not add snapshot fields to Quote or the global submission-hash preimage. `quoteId` is random 32 bytes, never derived from content, and is independently single-use in both the splitter mapping and DB. It also doubles as the single-use native-USDC authorization nonce; USDC nonce consumption is additional replay protection.

Native Base USDC authorization uses this exact domain and ordered primary type:

```ts
const usdcAuthorizationDomain = {
  name: 'USD Coin',
  version: '2',
  chainId: configuredBaseChainId, // 8453 in production
  verifyingContract: configuredNativeUsdcAddress,
};

const ReceiveWithAuthorization = [
  { name: 'from', type: 'address' },
  { name: 'to', type: 'address' },
  { name: 'value', type: 'uint256' },
  { name: 'validAfter', type: 'uint256' },
  { name: 'validBefore', type: 'uint256' },
  { name: 'nonce', type: 'bytes32' },
];
```

The exact primary type is `ReceiveWithAuthorization(address from,address to,uint256 value,uint256 validAfter,uint256 validBefore,bytes32 nonce)`. Production `verifyingContract` is canonical Base native USDC, currently `0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`. Before enabling checkout, verify runtime token `name()` and `version()`, chain ID/token address, and computed/onchain domain separator against configuration. Test tokens use their own actual domains and are labeled test-only.

The matching EIP-3009 authorization must be native USDC `receiveWithAuthorization(from=quote.payer, to=splitter, value=quote.attentionAmount+quote.gavelFeeAmount, validAfter=0, validBefore=quote.expiry, nonce=quote.quoteId, v, r, s)`. Browser/wallet checkout constructs and signs exactly these deterministic values and cannot choose its nonce or window. Settlement requires `block.timestamp < quote.expiry`; equality means both quote and authorization are expired. Binding the random quote ID as the authorization nonce cryptographically prevents an authorization for quote A from being paired with quote B, even when payer and total match. The splitter verifies the quote, `quoteVersion`, values, signer, expiry, every authorization binding, and `usedQuoteIds` before calling USDC. It calls `usdc.receiveWithAuthorization(...)` as both the authorization `to` and `msg.sender`; USDC's `msg.sender == to` requirement prevents a third party from redeeming a copied pending signature directly at USDC. The splitter then routes exact legs in one transaction and emits exactly:

```solidity
event QuoteSettled(
    bytes32 indexed quoteId,
    address indexed payer,
    address indexed voter,
    uint256 attentionAmount,
    address gavelRecipient,
    uint256 gavelFeeAmount,
    address token,
    bytes32 submissionHash
);
```

This complete declaration fixes the event signature and indexed fields. No extra event fields are part of settlement verification.

### Enrollment and wallet-auth contract

Implement the exact interoperable schemas and domain separation in normative technical specification [section 7.1](../GAVEL_GATE_TECHNICAL_SPEC.md#71-exact-eip-712-authentication-schemas), and the exact EOA/ERC-1271 chain behavior in [section 7.2](../GAVEL_GATE_TECHNICAL_SPEC.md#72-proof-behavior). `GateEnrollment` ordered fields are exactly `wallet,purpose,availability,dao,daoChainId,acceptPreVote,acceptVoting,attentionAmount,nonce,issuedAt,expiry,version`, with signed `purpose` fixed to `enrollment`. `WalletSession` ordered fields are exactly `wallet,role,audience,purpose,nonce,issuedAt,expiry,version`; role literals are exactly `base_sender`, `dao_profile`, and `dao_inbox`. `base_sender` derives configured Base chain/verifier; both DAO roles derive configured DAO chain/verifier, with no caller override. The same address on another chain grants no authority.

**DAO-chain enrollment EIP-712 payload** (Ethereum for Nouns):

```ts
const GateEnrollment = [
  { name: 'wallet', type: 'address' },
  { name: 'purpose', type: 'string' },
  { name: 'availability', type: 'string' }, // accepting_now | paused | closed
  { name: 'dao', type: 'string' },
  { name: 'daoChainId', type: 'uint256' },
  { name: 'acceptPreVote', type: 'bool' },
  { name: 'acceptVoting', type: 'bool' },
  { name: 'attentionAmount', type: 'uint256' },
  { name: 'nonce', type: 'bytes32' },
  { name: 'issuedAt', type: 'uint256' },
  { name: 'expiry', type: 'uint256' },
  { name: 'version', type: 'uint256' },
];
```

- `GateEnrollment.purpose` is the exact signed literal `enrollment`. The server challenge fixes it; clients cannot choose or override it.
- EOA: recover signer from typed-data signature and require exact wallet equality.
- Contract wallet/Safe: call ERC-1271 `isValidSignature(digest, signature)` on the DAO chain and require magic value `0x1626ba7e`.
- Wallet equals payout wallet always.
- A contract wallet must additionally sign a separate Base-chain EIP-712 `BasePayoutControl` challenge at enrollment and whenever transitioning to `accepting_now`. Using an injected bounded-time Base RPC, require current nonempty code, call ERC-1271 at the Base address, and atomically store `base_payout_code_hash = keccak256(currentCode)` with the accepting transition. The proof remains required; code-hash equality does not prove unchanged owners/controllers for an upgradeable wallet.
- Maintain a monotonic `profile_version`, incremented atomically on every profile/policy update including Base payout hash changes. One profile-scoped advisory/row lock, keyed only by voter/profile, is shared by every profile/policy update and every quote issuance for that profile. Quote issuance holds it through final rereads, contract-wallet code verification, canonical/limit/capacity checks, and quote transaction commit. This serializes all senders targeting the profile and prevents both profile-version/code-hash and global profile-capacity races. RPC failure/timeout rolls back, releases the lock, and persists no artifacts. EOAs skip the RPC. Already-issued valid quotes remain payable after later drift.
- EOA cross-chain identity needs no second proof.
- `/auth/challenge` may issue exact `GateEnrollment`, `BasePayoutControl`, or `WalletSession` challenges. Every GateEnrollment challenge fixes signed `purpose` to `enrollment` and persists it in `auth_nonces`; clients cannot choose another value. For WalletSession, it accepts only the three signed role literals, derives chain/verifier solely from role, and persists exact type + role + wallet + audience + chain + verifier + payload hash + expiry. `/auth/verify` atomically compares every value, verifies, consumes the nonce, and creates a wallet + role + chain + audience-bound session. Same-chain `dao_profile`/`dao_inbox` substitution fails.
- Profile writes require exact `dao_profile` role, receive exact `GateEnrollment` plus `BasePayoutControl` when required, and require exact equality among all proof/session wallets. They compare the exact signed `GateEnrollment.purpose == 'enrollment'` with the purpose persisted in `auth_nonces`, use the shared profile-scoped advisory/row lock, increment `profile_version`, and consume operation-proof nonces in the same DB transaction as the write. A missing, mutated, or wrong purpose fails verification without consuming a nonce or changing profile/policy state; every other validation failure or rollback has the same no-consumption/no-write behavior.
- Private inbox list/show/archive requires exact `dao_inbox` role and session wallet equal to the enrolled profile wallet. Submission creation, settlement submission/controls, and resume require exact `base_sender` role and session wallet equal to payer/signed sender. Public coarse status requires no session.
- Nonces are one-use, short-lived, persisted as consumed, and bound to exact type, exact signed `purpose` literal (`enrollment`, `base_payout_control`, or `wallet_session`), role, wallet, audience, chain, verifier, payload hash, and expiry as applicable. Any internal operation category is separate and never substitutes for signed `purpose`.

### Gate policy, availability, capacity, and canonical data

- Profile availability is global: `accepting_now`, `paused`, `closed`. No unpublished profile in MVP.
- Only `accepting_now` allows new quotes. Directory defaults to it; direct profiles remain public in every state and say “Not currently accepting new submissions” when unavailable.
- Per-DAO policy: enabled, accepted `VOTING`, attention price, public tags. `PRE_VOTE` stays in normalized adapter vocabulary only and MUST NOT be advertised or accepted for Nouns unless a real native mapping is separately frozen, implemented, and tested.
- Global rolling-24-hour capacity: default 25 settled submissions, private configurable value. A confirmed event is external truth, but settled capacity, reservation consumption, exactly one inbox item, notification enqueue, and reorg-monitor upsert become visible only together when their atomic DB transaction commits. The monitor key is `chainId + splitter + quoteId`; retry the entire transaction idempotently on DB failure. After commit, capacity counts immediately even if notification later fails, and accepted cannot exist without monitoring.
- Quote issuance creates a capacity liability. Active unexpired plus `expiry_pending_reconciliation` reservations are capped at `floor(capacity * 0.5)` (default 12). The one-active-quote rule counts only active unexpired quotes; an expired pair may proceed only if every global settled-capacity and pending-liability check passes. Wall-clock expiry never frees a slot. Scanner-safe no-match coverage releases; exceptional late pre-expiry settlement converts release to consumed. If late discovery/canonical rewrite causes temporary overcapacity, honor every paid inbox and block new issuance until the rolling count is below capacity.
- Separate rule: default max 2 settled submissions per signed sender per voter per proposal in the same rolling 24-hour window used by global capacity.
- Only successful quote issuance persists: immutable submission with NOT NULL issuance-snapshot FK, snapshot, quote, and reservation commit atomically under the profile-scoped advisory/row lock, with initial `QUOTED` / `payment_required`. Rejections persist no submission/snapshot/quote/reservation; private aggregate rate-limit events may still be written independently. Malformed input fails before hashing; rejected exact content may be retried unchanged.
- Generate each `publicId` independently of content, quote, wallet, proposal, hash, and timestamp using a CSPRNG with at least 128 bits of entropy and opaque URL-safe encoding. It is never sequential, timestamp-derived, hash-prefix-derived, wallet-derived, or enumerable. Enforce DB uniqueness and retry generation on collision without changing stable fields. Tests cover format/randomness, collision retry, non-derivation, and practical inability to guess neighboring IDs without claiming mathematical impossibility.
- `submission_hash` is globally unique across successfully quoted submissions. Its only implementation is `hashSubmission` imported from `@gavel/gate`; server, client, quote, and tests MUST NOT reimplement it. Canonicalize `payer` and `voter` with ethers `getAddress` to EIP-55, require `proposalId` to match exact unsigned decimal `0|[1-9][0-9]*` (no leading-zero variant), and compute ethers `keccak256(toUtf8Bytes(JSON.stringify(array)))` over exactly `["gavel-gate-submission-v1", payer, voter, dao, proposalId, stage, position, pitch, disclosures, evidenceUrls]` in that order. The domain tag and array shape/order are frozen; no field may be omitted, added, or reordered. Pitch/disclosures retain their exact JavaScript string bytes after JSON escaping—no trim, Unicode, whitespace, line-ending, or trailing-newline normalization—and evidence URL order is significant. After parse/size/Markdown/evidence validation, authenticate and require payer/sender equality, compute this canonical hash, and perform the owner-bound global lookup before mutable block/rate/profile/policy/index/lifecycle/limit/capacity checks. An owned match returns `duplicate` with `existing: { publicId, state, resumeUrl }` and never mutates or refreshes the row. If none exists, continue mutable checks; under the voter/profile-scoped advisory/row lock recheck hash before active quote/capacity/reservations. A concurrent same-hash unique-race loser returns the same duplicate response. Its path-only `resumeUrl` is `/v1/submissions/:publicId/resume` and requires the original wallet-bound session. Guessed IDs and direct-store/hash-collision fixtures fail closed without leakage.
- A second distinct submission while the sender × voter pair has an active unexpired quote is `rejected_by_policy` with stable coarse code `ACTIVE_QUOTE_EXISTS`. An otherwise-distinct third submission over the max-two settled sender/voter/proposal rolling-window limit is `rejected_by_policy` with code `SENDER_PROPOSAL_LIMIT`. Neither response reuses/leaks existing state, counts, or details, and neither issues a quote. Content changes evade neither limit.
- When capacity is exhausted, public profile/directory reports only “Not currently accepting new submissions”; never publish counts or reset time.
- A valid unexpired quote remains valid if availability, price, stage policy, or capacity changes after quote issuance.
- Current governance power is index-owned, public, exact, and shown with “as of” timestamp. It never changes availability. A zero-power profile can remain accepting.
- Nouns governance freshness SLA is configurable and defaults to 15 minutes. Store source block/hash, canonical refresh time, native state, normalized eligibility, mapping version, content hash, and actions in an issuance snapshot. Refuse quote issuance if the index is unhealthy/stale.
- Normalize lifecycle with DAO adapter output: `PRE_VOTE | VOTING | CLOSED`; preserve native state and adapter mapping version. The Nouns adapter receives upstream canonical labeled native state, maps only `ACTIVE` to `VOTING`, and fails every other value—including raw Governor numeric `1` and string `"1"`—closed to `CLOSED`; numeric codes must be normalized upstream. Generic `PRE_VOTE` remains vocabulary only, and Nouns quote issuance is `VOTING`-only until a real actionable native mapping is separately frozen, implemented, and tested.
- After Base confirmation, settlement processing MUST attempt exactly one current lifecycle read with a bounded timeout before or while constructing the atomic persistence transaction. The read is required but best-effort and non-vetoing. Success stores current state, sets `currentLifecycleUnavailable=false`, and sets `stateChangedAfterQuote=true` if and only if it differs from issuance. Unavailable/stale index or RPC, timeout, or unknown still commits settlement + reservation/capacity + inbox + notification enqueue atomically, retains issuance state, stores current lifecycle `UNKNOWN`, and sets distinct private `currentLifecycleUnavailable=true`. Never expose that field publicly, delay paid inbox creation, or retry lifecycle lookup on the settlement critical path. Later private enrichment/reconciliation may fill current lifecycle but cannot change acceptance. No other post-payment check may be rerun.

### Fact and content contract

- **Advocacy is permitted:** omissions, selective emphasis, disagreement, opinion, and rhetoric. MVP does not extract claims or flag prose.
- **MVP has no automated prose contradiction check.** It displays facts beside the raw pitch. Future deterministic checks may only use canonical and tested decoded facts.
- Fact model: `source: canonical | decoded | enriched`; `decoderVersion`, canonical action index/evidence, and display label. Enriched facts have only explicit strict fields `source`, `displayLabel`, `value`, and optional literal `verifiable: false`; canonical/decoded-shaped or unknown extras fail validation. Only canonical and tested decoded facts may ever be verification material; every verification serializer/consumer rejects enriched facts.
- Decode allowlist: native ETH `valueWei > 0`; exact `transfer(address,uint256)` selector/calldata decodes only when the action target is the configured allowlisted canonical Base native-USDC address. Ethereum/Nouns-chain USDC `0xA0b86991c6218b36c1d19d4a2e9eb0ce3606eb48` and every other token remain raw until a post-MVP chain-aware decoder. All proxy, delegatecall, multicall, unknown token, and arbitrary ABI-looking calldata remains raw.
- ENS and token metadata are enrichment only; display ENS with its address. Estimated block timestamps show “estimated” and Pacific Time.
- Pitch max 4,000 chars; disclosures max 2,000 chars; evidence max 5 URLs, HTTPS only. No uploads.
- Markdown AST allowlist: paragraphs/line breaks, headings, bold, italic, bullet/ordered lists, blockquotes, inline/fenced code, HTTPS links. Raw HTML, images, embeds, CSS, iframes, scripts, Mermaid, unsafe protocols, and every other disallowed AST node or URL make the submission `malformed`; they are rejected, never silently removed. The rendering parser uses `html: false`, and the renderer consumes that same validated token stream without reparsing. A separate HTML-enabled parser is permitted solely to detect/reject HTML and its tokens are never rendered. Allowed CommonMark survives validation unchanged and is rendered safely, preserving immutable accepted-content semantics. No autolink previews, server fetch, preview, scrape, summary, redirector, or tracking. Links render with an external indicator and `rel="noopener noreferrer"`.

### Private/public boundaries

**Public:** Gate wallet/ENS display, profile availability, DAO policy/stages/price/tags, exact current indexed power/as-of, public submission coarse state.

**Private to Gavel/voter:** enrollment signatures and nonce material, payout-control proof, quote signature, raw immutable submission, snapshot internals, inbox/read/archive state, capacity/rate data, notification channel/destination/result, IP data, sender blocks, logs beyond public receipt.

**Public submitter response states:** persisted receipts use `payment_required`, `pending_settlement`, `accepted` (means `inbox_created`), or `expired`; stateless responses may use `rejected_by_policy`, `malformed`, or `duplicate`. Public `expired` is payment-terminal but retains the canonical reconciliation qualification above. Rejections may omit `publicId` and are not resumable records.

**Public timestamps:** `acceptedAt` appears only for accepted and equals database-generated `inbox_created_at`, captured when the inbox row is inserted inside the atomic transaction via Postgres `clock_timestamp()` or an equivalent injected DB clock. It becomes visible only after commit, so accepted is never observable before `INBOX_CREATED`; it is not receipt block time, transaction-start time, notification/delivery/read time, or a promise of the precise commit instant. Coarse Gate state-transition `updatedAt` appears only for payment-required/pending/expired and carries no delivery/read meaning. Duplicate/rejected/malformed expose no timestamp. Receipt block number/hash/timestamp is private settlement evidence.

The only authenticated API-session transport in MVP is `Authorization: Bearer WALLET_SESSION`. Secrets never appear in URLs, request bodies, or logs. `GET /v1/submissions/:publicId/resume` requires the exact Base-chain original-sender session and may return original quote/payment/resume controls. `GET /v1/submissions/:publicId/status` is deliberately public by random opaque ID and returns only coarse state plus the enumerated safe timestamp, never quote/payment/resume/private data or controls. Submission, quote, settlement, resume, and public status responses set `Cache-Control: no-store` and `Referrer-Policy: no-referrer`.

One settlement transaction locks the quote, verifies `quoteVersion == 1`, expected event fields, and pre-expiry inclusion before mutation, then atomically marks settlement exactly once, converts/reconciles even a released reservation to final consumed/counts settled capacity exactly once, creates exactly one inbox row, enqueues the notification, and upserts the reorg monitor by `chainId + splitter + quoteId`.
